# Kiến Trúc & Quy Ước Dự Án — Full-Stack Next.js

> Dự án áp dụng **Clean Architecture** (Robert C. Martin) kết hợp **Domain-Centric design** và **Atomic Design** cho UI.
> Mục tiêu cốt lõi: **Business logic không phụ thuộc vào framework, database, hay UI.**

## 1. Triết lý — Clean Architecture

> **Clean Architecture áp dụng cho CẢ HAI phía: Frontend (FE) và Backend (BE).**
> Mỗi phía đều có 4 vòng layer riêng biệt. **Tầng Entities là tầng DUY NHẤT được chia sẻ.**

```text
╔══════════════════════════════════╗     ╔══════════════════════════════════╗
║         FRONTEND (Browser)       ║     ║         BACKEND (Server)         ║
║                                  ║     ║                                  ║
║  🟡 Frameworks & Drivers         ║     ║  🟡 Frameworks & Drivers         ║
║     React, Zustand, Next.js      ║     ║     Next.js, Drizzle, SQLite     ║
║  ┌────────────────────────────┐  ║     ║  ┌────────────────────────────┐  ║
║  │ 🟢 Interface Adapters      │  ║     ║  │ 🟢 Interface Adapters      │  ║
║  │   Repository (HTTP client) │  ║     ║  │   Route Handler            │  ║
║  │   Mapper (DTO→Domain)      │  ║     ║  │   ORM Layer (Drizzle)      │  ║
║  │ ┌────────────────────────┐ │  ║     ║  │ ┌────────────────────────┐ │  ║
║  │ │ 🔵 Use Cases           │ │  ║     ║  │ │ 🔵 Use Cases           │ │  ║
║  │ │   Store Handler        │ │  ║     ║  │ │   Service (Server)     │ │  ║
║  │ │   Service (Client)     │ │  ║     ║  │ │   Auth Guard           │ │  ║
║  │ │ ┌────────────────────┐ │ │  ║     ║  │ │ ┌────────────────────┐ │ │  ║
║  │ │ │ ⚪ Entities        │ │ │  ║     ║  │ │ │ ⚪ Entities        │ │ │  ║
║  │ │ │  ITodo, IUser      │◄├─╫─────────╫─►│ │  ITodoDTO, IUserResponse│ │ │  ║
║  │ │ │  IRepository       │ │ │  ║SHARED║  │ │ │  (same types.ts)  │ │ │  ║
║  │ │ └────────────────────┘ │ │  ║     ║  │ │ └────────────────────┘ │ │  ║
║  │ └────────────────────────┘ │  ║     ║  │ └────────────────────────┘ │  ║
║  └────────────────────────────┘  ║     ║  └────────────────────────────┘  ║
╚══════════════════════════════════╝     ╚══════════════════════════════════╝
              │                                          ▲
              │         HTTP (JSON — DTO only)           │
              └──────────────────────────────────────────┘
```

**Quy tắc phụ thuộc:** Mũi tên chỉ hướng vào trong.
Layer bên trong **không bao giờ** biết layer bên ngoài tồn tại.

### Mỗi layer thuộc về FE hay BE?

| Circle                | Layer                      | 🌐 Frontend                     | ⚙️ Backend                     |
| --------------------- | -------------------------- | ------------------------------- | ------------------------------ |
| ⚪ Entities           | Domain Models + Interfaces | `ITodo`, `IUser`, `IRepository` | `ITodoDTO`, `IUserResponse`    |
| 🔵 Use Cases          | Business Logic             | `StoreHandler`, `ServiceClient` | `ServiceApi`, `AuthGuard`      |
| 🟢 Interface Adapters | Kết nối layers             | `Repository`, `Mapper`          | `Route Handler`, `Drizzle ORM` |
| 🟡 Frameworks         | Công cụ & Framework        | `React`, `Zustand`, `Next.js`   | `Next.js`, `Drizzle`, `SQLite` |

## 2. Cấu Trúc Thư Mục (Domain-Centric)

Toàn bộ logic nghiệp vụ được tổ chức theo module trong thư mục `src/domains/`.

```text
src/
├── app/                                # Next.js App Router
│   ├── (main)/docs/                   # Trang tài liệu này
│   └── api/
│       └── [module]/
│           ├── route.ts               # Route Handler (Framework)
│           └── [module].service.ts    # Server-only business logic (Use Case)
│
├── domains/                           # ⚪&🔵 CORE — Entities & Use Cases
│   └── [module]/
│       ├── [module].types.ts          # DTO + Domain Model + Interfaces
│       ├── [module].mapper.ts         # Mapper (Interface Adapter)
│       ├── [module].service.ts        # Client-side Service (Use Case)
│       ├── [module].repository.ts     # HTTP Implementation (Adapter)
│       └── [module].repository.mock.ts # Mock data (Adapter)
│
├── store/                             # 🟢 Interface Adapters — State
│   └── [module]-store/
│       ├── [module]-store.handler.ts  # Logic thay đổi state (Use Case)
│       └── [module]-store.types.ts    # Định nghĩa State
│
├── hooks/                             # 🟢 Interface Adapters — Hooks
│   └── [module]/
│       └── use-[module]-ssr.ts        # Zustand Context Bridge
│
├── components/                        # 🟡 Frameworks — UI (Atomic Design)
│   ├── atoms/                         # Button, Input, Badge
│   ├── molecules/                     # Form, Card, Providers
│   └── organisms/                     # Feature blocks: TodoView
│
├── db/                                # 🟡 Frameworks — Database
└── utils/                             # Shared utilities
```

### Phân loại theo Clean Architecture circle

```text
domains/[m]/[m].types.ts          ← ⚪ Entities
domains/[m]/[m].service.ts        ← 🔵 Use Cases
app/api/[m]/[m].service.ts        ← 🔵 Use Cases
store/[m]-store/[m]-store.handler ← 🔵 Use Cases
domains/[m]/[m].mapper.ts         ← 🟢 Interface Adapters
domains/[m]/[m].repository.ts     ← 🟢 Interface Adapters
app/api/[m]/route.ts              ← 🟢 Interface Adapters
components/                       ← 🟡 Frameworks & Drivers
app/ (Next.js routing)            ← 🟡 Frameworks & Drivers
db/ (Drizzle + SQLite)            ← 🟡 Frameworks & Drivers
```

┌─────────────────────────────────────────────────────────────────────┐

│  │  molecules    │ → View Layer (React Components)                  │
│  │  organisms    │                                                  │

│         │  Gọi selector / dispatch action                           │

│  │  Custom Hook  (use[Module]SSR)               │                  │

│  │  Tách biệt Store khỏi Component             │                  │

│         │  Đọc/ghi state                                            │
│         ▼                                                           │
│  ┌──────────────────────────────────────────────┐                  │
│  │  Store Handler  (Zustand)                    │  ← Use Case      │

│  │  - Rollback khi lỗi                          │                  │

│         │  Gọi method qua interface IRepository                     │

## 5. Luồng Backend (Server Side)

```text
                       HTTP Request từ Browser
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│                         BACKEND FLOW                                │
│                                                                     │
│  ┌──────────────────────────────────────────────┐                  │
│  │  Route Handler  app/api/[module]/route.ts    │  ← Framework     │
│  │  - Entry point duy nhất                      │    Driver        │
│  │  - Parse request (URL params, body)          │                  │
│  │  - Gọi Auth Guard trước mọi operation        │                  │
│  │  - Trả NextResponse.json()                   │                  │
│  └──────┬───────────────────────────────────────┘                  │
│         │                                                           │
│         ▼                                                           │
│  ┌──────────────────────────────────────────────┐                  │
│  │  Auth Guard  AuthServiceApi                  │  ← Use Case      │
│  │  - Đọc HTTP-only cookie                      │                  │
│  │  - jwtVerify(token, ENV_SERVER.JWT_SECRET)   │                  │
│  │  - Trả userId nếu hợp lệ, null nếu không    │                  │
│  │  - Route trả 401 ngay nếu null               │                  │
│  └──────┬───────────────────────────────────────┘                  │
│         │  userId hợp lệ ✅                                         │
│         ▼                                                           │
│  ┌──────────────────────────────────────────────┐                  │
│  │  Service (Server)  api/[module]/[m].service  │  ← Use Case      │
│  │  - Chứa toàn bộ business logic server        │                  │
│  │  - Không biết gì về HTTP, Next.js            │                  │
│  │  - Luôn scope query theo userId              │                  │
│  │  - Chỉ trả về DTO (không trả Domain Model)  │                  │
│  └──────┬───────────────────────────────────────┘                  │
│         │                                                           │
│         ▼                                                           │
│  ┌──────────────────────────────────────────────┐                  │
│  │  ORM Layer  Drizzle ORM                      │  ← Interface     │
│  │  - Type-safe SQL queries                     │    Adapter       │
│  │  - Schema định nghĩa ở db/schema.ts          │                  │
│  │  - Tự động returning() raw row               │                  │
│  └──────┬───────────────────────────────────────┘                  │
│         │                                                           │
│         ▼                                                           │
│  ┌──────────────────────────────────────────────┐                  │
│  │  Database  SQLite (better-sqlite3)           │  ← Framework     │
│  │  - Persistent storage                        │    Driver        │
│  │  - Có thể swap sang PostgreSQL               │                  │
│  └──────────────────────────────────────────────┘                  │
└─────────────────────────────────────────────────────────────────────┘
```

### Naming convention — Server vs Client Service

| File                             | Chạy ở đâu      | Export                        |
| -------------------------------- | --------------- | ----------------------------- |
| `src/domains/[m]/[m].service.ts` | **Client**      | `[Module]ServiceClient` class |
| `src/app/api/[m]/[m].service.ts` | **Server only** | `[Module]ServiceApi` object   |

## 10. Optimistic Update

1.  **UI Action**: User tick hoàn thành todo.
2.  **Optimistic State**: Store cập nhật local state ngay lập tức, `pendingCount++`.
3.  **Network**: Call API trong background.
4.  **Sync**:
    - **Thành công**: Cập nhật data thật từ server (real ID), `pendingCount--`.
    - **Thất bại**: Rollback state cũ, báo lỗi, `pendingCount--`.

## 11. Phong Cách Code & Quy Ước

### 11.1 "Triết lý về Hợp đồng (Contract)"

Zod schemas KHÔNG thuộc về Domain. Chúng là **Hợp đồng Validation** giữa UI (React Hook Form) và Logic Ứng dụng (UseCase).

- **Quy tắc**: Giúp giữ quy tắc validation gần nơi sử dụng (Forms/Hooks).
- **Thực thi**: Dùng `schema.parse()` trong UseCases để kiểm tra đầu vào nghiêm ngặt trước khi thực hiện logic nghiệp vụ.

### 11.2 Zustand Stores

- **Store Handlers**: Dùng Store Handlers để đóng gói các thay đổi state phức tạp, giữ cho component sạch sẽ.
- **Performance**: Dùng `Object.assign(state, handler)` thay vì object spread `{ ...state, ...handler }` để cập nhật state hiệu quả hơn.
- **Selective Rendering**: Luôn dùng `useShallow` và **Selector** để chỉ re-render những gì cần thiết.

### 11.3 Chi tiết Quy Ước Đặt Tên

Để cả team làm việc trơn tru, hãy tuân thủ các quy tắc đặt tên sau:

#### 📂 Use Cases

- **File**: `[action].use-case.ts` (vd: `create.use-case.ts`)
- **Class**: `[Action][Module]UseCase` (vd: `CreateTodoUseCase`)

#### 📂 Repositories

- **Interface**: `I[Module]Repository` (nằm trong `domains/[module]/`)
- **Implementation**: `Http[Module]Repository` hoặc `Mock[Module]Repository` (nằm trong cùng folder).

#### 📂 Components

- **Thư mục**: Dùng **kebab-case** (vd: `todo-item-card`).
- **File Component**: Dùng **PascalCase** (vd: `index.tsx`).

> [!TIP]
> **Lời khuyên**: Nếu thấy logic bắt đầu "phình to" ở UI, hãy nghĩ ngay đến việc tách nó ra một **UseCase** hoặc **Store Handler**. UI chỉ nên biết "nút này bấm vào thì gọi hàm gì", đừng để UI biết "hàm đó gọi API nào".

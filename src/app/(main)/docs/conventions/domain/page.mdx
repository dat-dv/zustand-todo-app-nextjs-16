# Domain Layer

Trái tim của ứng dụng. Logic nghiệp vụ phải thuần khiết, không phụ thuộc UI, API hay thư viện nào khác.

---

## 1. Cấu trúc

Mỗi tính năng sẽ nằm trong `src/domain/todo/`:

| Thư mục             | Trách nhiệm                                 |
| ------------------- | ------------------------------------------- |
| **model/**          | Định nghĩa **Entity** (vd: `ITodo`)         |
| **infrastructure/** | Repository hiện thực (vd: `TodoRepository`) |
| **use-cases/**      | Chứa các hành động xử lý nghiệp vụ đơn lẻ   |

---

## 2. Quy trình vận hành

Dự án dùng mô hình **Adapter-Centric**: Hook (Adapter) điều phối hoạt động giữa UI, Store và Use Case.

### 4.1 Luồng Truy vấn (Query Flow)

- **UI**: Gọi `fetchTodos()` từ Hook.
- **Hook (Adapter)**: Bật trạng thái loading và gọi `FindAllTodosUseCase.execute()`.
- **UseCase**: Điều phối logic và gọi `Repository.findAll()`.
- **Repository**: Fetch data từ API/DB -> Dùng **Mapper** chuyển DTO thành **Domain Entity**.
- **Result**: Data được trả lại cho Hook để cập nhật Store và re-render UI.

### 4.2 Luồng Hành động (Command Flow)

_Sử dụng khi thay đổi dữ liệu (Create/Update/Delete)._

- **Optimistic**: Hook có thể cập nhật Store ngay lập tức để tạo cảm giác "siêu tốc".
- **UseCase**: Đảm bảo các quy tắc nghiệp vụ (vd: k cho xóa nếu chưa hoàn thành).
- **Repository**: Thực thi tầng hạ tầng và mapping kết quả trả về.
